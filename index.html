§1

Abstract

Large language models are now everyday tools for learning and writing about history, and they are very good at telling stories. That strength is also a weakness. Asked about a famous event, a model will usually blend well-attested facts, open scholarly disputes and late legends into one smooth narrative, and the reader cannot see the joins.

This project presents Veritale, a skill file that lets an AI agent turn historical events and dates into a timeline and a story while labelling every claim as Verified, Disputed or Legend. The skill is written in Markdown and follows the Agent Skills format. A short entry file, SKILL.md, directs the agent through six modules: intake, fact table, evidence grading, timeline, narrative, and an uncertainty note with a self-check. The agent opens each module only when it reaches that step.

The design was tried out on two case studies with well-known source problems: the Norman Conquest of 1066 and Ashoka's Kalinga war of c. 261 BCE. Together they produced 35 graded claims, of which 18 were Verified, 9 Disputed and 8 Legend, and every factual claim in the two stories could be traced back to a row in the fact table. The modular layout meant the agent read between 51 and 60 per cent of the skill's text for a typical task, instead of all of it.

The project argues that source criticism, one of the oldest habits of the historian's craft, can be written down as plain instructions that an AI agent can follow. It also sets out the limits of the approach, above all the agent's dependence on its own memory of the sources.

Keywords: digital humanities, large language models, agent skills, historiography, source criticism, evidence grading, hallucination, modular prompt design

§2

Introduction

Ask a chatbot how King Harold died and you will probably be told that an arrow hit him in the eye. Ask how Ashoka changed after Kalinga and you may read that he walked across the battlefield, wept, and became a Buddhist. The first story is disputed. The second has no early source at all. Neither answer is a hallucination in the usual sense, because both stories really do appear in books. The trouble is that the model tells them in the same confident voice it uses for dates nobody doubts.

Historians have long had a way of dealing with this. We ask where a claim comes from, how close that source stood to the event, and who else says the same thing. Marc Bloch described this questioning as the core of the historian's craft, and Sam Wineburg later showed how differently trained historians and school students read the same documents. Language models do not question their sources unless they are told to, and even then they do it unevenly.

Agent Skills offer a practical way to tell them. A skill is a folder of instructions, written in Markdown, that an agent loads when a task calls for it (Anthropic, 2025). At first the agent sees only a short description. It opens the full instructions when the task matches, and any further files only when the instructions point to them. Because of this layered loading, a skill can be detailed without crowding the model's working context.

I studied History before moving into digital humanities, and this project grew out of a simple wish: to let an AI tell a good story without hiding the evidence behind it. The name Veritale joins veri-, from the Latin for truth, with tale. The aim is a story that keeps faith with its sources.

§3

Project objectives

  1. To design a reusable skill file that turns historical events and dates into a graded timeline and a readable story.
  2. To define a three-label scheme (Verified, Disputed and Legend) with ordered decision steps that an AI agent can apply the same way each time.
  3. To split the skill into modules that the agent loads only when needed, and to measure how much reading this saves.
  4. To test the skill on two case studies from different regions and periods, each with known disputes and legends.
  5. To publish the files, the method and the limits on an open website that others can read, cite and build on.
§4

Research questions

The project is built around two questions. The first is about history; the second is about design.

RQ1

Can a written skill file make an AI agent separate verified historical facts from disputed claims and legends when it turns events and dates into a story?

Answered in §9.1 with the label counts, the claim splits and the traceability check from both case studies.

RQ2

How does splitting the skill into modules change how much instruction the agent must read, and how easy the skill is to check and revise?

Answered in §9.2 with word counts for each file and for each mode of use.

§5

The skill and its modules

Veritale has one entry file and seven supporting files. SKILL.md is short on purpose. It names the three labels, lists seven hard rules, and tells the agent which module to open at each step. The modules hold the detail, and each one follows the same pattern: purpose, steps, rules, output and checks.

        §8

        Methodology

        Design approach

        The work followed a design-based approach. I began with the questions a history teacher asks of any source, then rewrote them as steps an agent could carry out without help. Wineburg's heuristics of sourcing and corroboration were the starting point: check who wrote a document and when, and check whether other documents agree. Distance in time became the test for the Legend label, and disagreement between credible sources became the test for Disputed.

        Choice of format

        The skill follows the Agent Skills format. SKILL.md opens with a block of metadata holding the name and a description of when to use the skill. The body sets out the workflow, and the supporting files hold the detail. I kept SKILL.md under 80 lines so that it could act as a map rather than a manual.

        The label scheme

        Evidence grading is common in medicine, where the GRADE system rates how far a body of evidence can be trusted (Guyatt et al., 2008). Veritale borrows the idea and keeps it small. Three labels are enough for a school pupil to understand, and they map onto the distinctions historians already make between agreed fact, open debate and later tradition.

        Case selection

        The two cases were chosen because they differ in almost every way that matters for source criticism. Hastings rests on chronicles, a woven hanging and later monastic histories, all from western Europe. The Kalinga war rests on royal inscriptions in Prakrit, on Buddhist texts written centuries afterwards, and on colonial-era decipherment. Both topics carry famous stories with weak support, which made them a fair test.

        Procedure

        1. Run the skill on each case in full mode, one module at a time, and keep the output of every step.
        2. Check each graded claim by hand against standard scholarship: Morillo (1996), Lawson (2002) and Davis and Chibnall (1998) for Hastings; Thapar (1961), Strong (1983) and Hultzsch (1925) for Ashoka.
        3. Count the labels, and confirm that every factual claim in each story links to a row in the fact table.
        4. Count the words in each file and work out how much the agent reads in each mode.

        Analysis

        9.1 RQ1: separating fact, dispute and legend

        The skill produced 18 graded claims for Hastings (9 Verified, 5 Disputed and 4 Legend) and 17 for the Kalinga war (9 Verified, 4 Disputed and 4 Legend). Every famous anecdote in the two topics survived into the story, but none of them appeared in a plain factual voice. The lone axeman at Stamford Bridge, William's fall on the beach, Edith Swan-neck, the altar at Battle Abbey, the ninety-nine brothers, "Ashoka's hell", the converting monk and the 84,000 stupas were all labelled Legend and introduced with words such as "a later story says".

        The most useful rule turned out to be the smallest one. Module 2 tells the agent to split compound claims. That rule turned "Harold died at Hastings from an arrow" into two rows: his death, which is Verified, and the arrow, which is Disputed. It did the same for the casualty figures in Ashoka's Rock Edict XIII. The claim that the edict gives those numbers is Verified, while the claim that the numbers are a true count is Disputed. Without the split, the agent would have had to give each sentence a single label, and that label would have been either too strong or too weak.

        Traceability held in both stories. All 35 claims appear in the narratives, and the build check found no factual statement outside the fact table. The only unlinked sentences are short links such as "Harold's first test came from the north" and "We know this from his own words". These make up about 10 per cent of the Hastings story and 14 per cent of the Kalinga story.

        Two cases showed where judgement is still needed. The Third Buddhist Council is known only from much later Sri Lankan sources, so step 1 of the grading module points towards Legend. Yet many historians accept that some kind of council took place. I graded it Disputed, which the "choose the weaker label" rule does not settle on its own. Ashoka's death in c. 232 BCE raised the opposite problem. The event is certain and only the year is approximate, so the label stays Verified and the doubt moves into the "c." of the date.

        9.2 RQ2: what modularity changes

        The whole skill holds 5,452 words across eight files. SKILL.md accounts for 759 of them, about 14 per cent. Before a task begins, the agent sees only the 45-word description.

        A full run reads 40 per cent less than a single-file version of the same content, and a timeline-only run reads 49 per cent less. Most of the saving comes from the worked examples, which are long and are only needed when the agent is unsure what good output looks like.

        The second benefit is easier to see than to count. Because each concern lives in its own file, a change has a clear home. Rules about dates sit only in module 4, and advice on tone sits only in module 5, so revising one does not risk breaking the other. Each module also ends with its own checks, which gives a reviewer a short list to test against. This benefit is a design observation; I have not yet measured it with other editors.

        §10

        Discussion

        The main finding is that source criticism can be written down. The habits a history student picks up slowly over years, such as asking who wrote a text, how long after the event and who agrees, translate fairly well into short, ordered instructions. The agent does not need to understand historiography in any deep sense to follow "split compound claims" or "choose the weaker label when unsure".

        The labels are less about truth than about honesty of voice. Veritale cannot make a model know more than it knows. What it changes is how the model speaks about what it knows. A legend is still told, but it is told as a legend. That matters for teaching, because Wineburg found that students often read a textbook as if it had no author and no point of view. A story that names its sources at every turn works against that habit.

        Honesty also costs words. In the Hastings story, Disputed and Legend claims take up 60 per cent of the text even though they are only half of the claims, because each one needs a framing phrase and often both sides of an argument. In the Kalinga story the figure is 41 per cent. The student version with inline labels reads in a more broken-up way than the version for general readers. This is a real trade-off between flow and transparency, and the audience setting in module 1 is where a user can choose between them.

        The modular design suits humanities work more widely. Modules 2 and 3, the fact table and the grading, could sit under a different output module, for example one that writes museum labels, a podcast script or a classroom quiz. The evidence step would stay the same while the telling changes.

        Finally, the skill shifts trust but does not remove it. A reader now has to trust the grading instead of the story. Because the same model does both, the labels are only as good as the model's recall of the sources. That is why the next section begins where it does.

        §11

        Limitations

        The project is a working design and a small pilot, not a full evaluation. Its limits are listed here so that anyone who uses or extends it knows where to be careful.

        1. The agent relies on its own memory

          Veritale cannot open an archive. It grades claims using whatever the model remembers about the sources, and a model can misremember a source or attach a real story to the wrong text. The rules forbid inventing sources, but a written rule cannot enforce itself.

        2. A small test

          Two case studies, checked by one person, cannot show how the skill performs across many topics, models and readers. The results show that the design can work, not how often it does.

        3. Three labels flatten nuance

          Verified covers both a royal inscription and a later chronicle that historians trust. Disputed groups an argument about a date with an argument about whether something happened at all. Some legends also keep a kernel of real history.

        4. Grading needs judgement

          The Third Buddhist Council shows that two careful graders could disagree. There is no test yet of agreement between different models, or between a model and trained historians.

        5. The source base has its own bias

          "Broad agreement among historians" can carry colonial or Eurocentric assumptions, and oral traditions can be pushed into the Legend label unfairly. The skill grades by the age and type of a source, which tends to favour written and official records.

        6. Words are not tokens

          The load figures count words, while models count tokens, and the saving only holds if the agent actually follows the instruction to open modules one at a time.

        7. Language and platform

          The skill is written in English and has not been tried with sources in Hindi, Sanskrit, Persian or other Indian languages. It also needs an agent that supports skills; in an ordinary chat the files have to be pasted in by hand.

        §12

        Conclusion and future work

        Veritale shows that an AI agent can be guided to tell history as a story while keeping its evidence in view. In two very different case studies, the skill kept every famous legend but never let one pass as fact, and its modular layout cut the agent's reading by 40 to 49 per cent compared with a single file. The approach is simple enough for a teacher to read and change, which matters as much as how well it works.

        The next steps are clear. The skill should be tested on a larger set of topics drawn from many regions and periods, with two trained historians grading the same claims so that agreement can be measured. A retrieval module that links each claim to a digitised source would reduce the reliance on memory. A Hindi version, and a short study with school and college students, would show whether the labels actually help readers think about evidence.

        §13

        Using the skill

        All the files sit in the repository at the same level, so the skill works as one folder.

        1. Get the files

          Download the repository from GitHub and keep SKILL.md, the six module files and examples.md together in one folder named veritale.

        2. Add it to an agent

          Install the folder as a skill in any agent that supports the Agent Skills format. In a plain chat, paste SKILL.md first and then each module when the agent reaches that step.

        3. Ask a history question

          For example: "Tell the story of the Battle of Plassey for my class", or "Give me an evidence-graded timeline of the fall of Vijayanagara."

        4. Read the labels

          Check the timeline labels and the "What we are unsure about" note, then follow up on anything marked Disputed or Legend.

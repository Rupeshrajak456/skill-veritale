# Module 2: Fact table

Part of the Veritale skill. Read `SKILL.md` first.

## Purpose

Collect every claim the answer will rely on, before writing a single sentence of story. The table is the evidence base. If a claim is not in the table, it does not appear in the story.

## Table format

| ID | Date | Claim | People | Earliest source | Source type | Notes |
|---|---|---|---|---|---|---|
| C1 | 1066, 14 Oct | Battle of Hastings fought; William defeats Harold | William, Harold II | Anglo-Saxon Chronicle; William of Poitiers (c. 1070s) | Contemporary chronicle | |

Number the claims C1, C2, C3 and so on. Later modules refer to these IDs.

## Source types

Record the type of the earliest source you know for each claim. Module 3 uses this column to grade.

| Source type | Examples |
|---|---|
| Primary, contemporary | Inscriptions, coins, letters, official records, eyewitness accounts |
| Near-contemporary chronicle | Written within roughly a generation of the event |
| Later chronicle | Written two or more generations after the event |
| Tradition or hagiography | Religious lives, folk stories, court legends, family histories |
| Modern scholarship | Peer-reviewed work that weighs the sources |

## Steps

1. List the main events in the chosen scope.
2. Add the details you might want to use in a story: who was there, numbers, famous incidents, causes and results.
3. Split compound claims. "Harold died at Hastings from an arrow" is two claims: that he died there, and how he died. They may get different labels.
4. Separate the source from the event. When a single source gives a figure, record the claim as "Source X states ...", and add a second row for the event itself if needed.
5. For every claim, write the earliest source you can name. If you cannot name one, write "source uncertain". Never make up a source, a page number or a quotation.
6. Use the Notes column for conflicts. If two sources give different dates or details, write both.

## Rules

- One claim per row.
- Dates follow the forms in module 4. Use "c." for approximate dates.
- Keep the table even when the user only wants a story. You do not have to print it, but you must build it.
- Aim for 8 to 20 rows for a medium-length answer. Fewer rows usually means missing context; more rows usually means the scope is too wide.

## Common mistakes

- Adding vivid details from memory without a source. If it is not in the table with a source, leave it out.
- Treating a famous film, novel or popular website as a source.
- Merging the date of a battle with the date of the treaty that ended the war.
